# Rowan code review

- **Date:** 2026-09-16T13:07:11-0700
- **Model:** Grok 4.6
- **HEAD:** `c2f548d` (`cleanup, fixes - see bugs.md`)
- **Scope:** Whole-project review of `@rowan-ui/core`, `@rowan-ui/maplibre`, `@rowan-ui/icons`, docs, tests, and packaging. This is not a branch diff; `main` is clean and matches `origin/main`.
- **Prior findings:** F-01 through F-25 in `bugs.md` were treated as closed unless current code still exhibits the defect.

## Summary

Rowan is a well-engineered vanilla Web Component design system. After the F-01–F-25 pass, the foundation is coherent: `BaseElement` owns FACE, token fallbacks, and listener lifecycle; modals sit on native `<dialog showModal()>`; table/virtual-list virtualization and scroll anchoring are real; XSS hygiene is strong (`textContent`, constrained rich-text documents, `sanitizeNavigationHref`).

The remaining defects are current and user-visible. The ones that will actually break product forms or pages are: `rowan-radio-group` `required` implemented as “first child is required,” `rowan-number-field` wiping in-progress input, `accept` not applying to drops, `rowan-row-details-panel` leaking body scroll lock on disconnect, date-only `formatDate` shifting a calendar day west of UTC, and `css:check` importing a Node 22 API while CI is Node 20. Overlay stacking outside the native-dialog family (popover, dropdown, toaster, context-menu) is the other concentrated risk.

**Issue counts:** 16 bugs, 12 suggestions, 3 nits.

## Issues

### Issue 1 -- Severity: bug
- File: src/radio-group/radio-group.js:97
- Description: `rowan-radio-group` is not form-associated. `required` is implemented by setting `radio.required = true` on index 0 only. Each `rowan-radio` then validates independently (`src/radio/radio.js:230`: `if (this.required && !this.checked)`). Selecting a later radio unchecks the first but leaves it `required`, so `checkValidity()` on the first child is still false while the group has a valid selection. Native radio `required` is group-level: any checked peer satisfies it. `rowan-form-wizard` and `rowan-validation-summary` walk descendant FACE `checkValidity()`, so a completed required group still blocks Next/Complete and surfaces a spurious error. Tests assert that only the first child is required; they never assert form validity after selecting a later option.
- Suggestion: Make the group `formAssociated` and own `required` / `setFormValue` / `setValidity` there, and do not mark child radios required. Alternatively, when any owned radio with the same name is checked, clear `valueMissing` on every owned radio. Add a test: required group, select the second option, `form.checkValidity()` is true.
- Status: open

### Issue 2 -- Severity: bug
- File: src/number-field/number-field.js:7
- Description: Every `input` event assigns `this.value = this.#input.value`, which runs `/^[+-]?(?:\d+|\d*\.\d+)$/` and stores `""` for incomplete-but-legal typing (`-`, `1.`, `.5` mid-edit, `1e2`). Render then does `this.#input.value = this.value` (`src/number-field/number-field.js:304`). For `type="number"`, writing `""` (or a truncated `"1"`) clears the browser’s unsanitized text buffer, so the user cannot type a leading minus or a decimal. `rowan-text-field` already skips write-back while composing and when the inner value matches; number-field does not. The same write-back pattern exists on `rowan-time-picker` and `rowan-date-picker`.
- Suggestion: Keep a raw store while focused, or skip write-back when the inner control is focused / `validity.badInput` is true. Normalize on `change`, stepper clicks, and form submit. Align accepted strings with `Number(...)`.
- Status: open

### Issue 3 -- Severity: bug
- File: src/dropzone/dropzone.js:207
- Description: `accept` is copied onto the hidden `<input type="file">` so the OS picker filters, but `#emitFiles` never matches files against `accept`. `rowan-file-upload.#acceptFiles` likewise only applies `multiple` and `max-files`. A dropzone with `accept=".csv,.pdf"` will still queue a dropped `.exe`. Tests only assert that the attribute reflects onto the input. There is no size cap; the documented `accept` contract is the only client-side gate, and drop bypasses it.
- Suggestion: Parse `accept` (extensions, MIME types, `image/*` wildcards) and filter both picker `change` and `drop` before emitting `rowan-files-add`. Apply the same filter in `rowan-file-upload.#acceptFiles` so a synthetic event cannot bypass it. Report rejected files.
- Status: open

### Issue 4 -- Severity: bug
- File: src/row-details-panel/row-details-panel.js:169
- Description: An open `rowan-row-details-panel` calls `pushOverlay(this)` on open. `disconnectedCallback` closes the native `<dialog>` but never calls `removeOverlay(this)` and never clears `#isOpen`. `pruneDisconnectedOverlays()` in `src/lib/overlay-stack.js:29` runs only from `pushOverlay` / `removeOverlay`, so removing the last open panel leaves `document.body.style.overflow = "hidden"` until some other overlay later mutates the stack. The page is interactive (native modal is already closed) but cannot scroll. `rowan-dialog` and `rowan-command-palette` avoid this by unregistering on disconnect; the dialog suite even documents the lazy prune as needing a later overlay update.
- Suggestion: On disconnect, call `removeOverlay(this)` and reset `#isOpen`, matching `src/dialog/dialog.js:35`. Optionally prune eagerly from the stack so a missed caller cannot leak the lock. Add a regression that opens a details panel, removes it, and asserts body overflow is restored with no further overlay activity.
- Status: open

### Issue 5 -- Severity: bug

- Description: `rowan-drawer` does call `removeOverlay` on disconnect, but it does not set `#isOpen = false`. On reconnect while `open` is still true, `#syncOpenState` hits `if (this.open === this.#isOpen) return` and skips `#onOpen()` / `pushOverlay`. `#reconcileNativeOpen()` still calls `showModal()`, so the drawer looks modal but is absent from the stack and body scroll is not locked. `rowan-row-details-panel` has the same `#isOpen` short-circuit at `src/row-details-panel/row-details-panel.js:566`. ### Issue 6 -- Severity: bug
- File: src/lib/base-element.js:194
- Description: `setCustomValidity` stores `#customValidityMessage` and `requestRender()`s. `applyValidity` (the only writer of the custom error into `ElementInternals`) runs later in the render microtask, and that microtask no-ops when `!this.isConnected`. Native `setCustomValidity` is synchronous: `el.setCustomValidity("taken"); el.reportValidity()` / `el.validity.customError` must already reflect the error. The F-07 test awaits a microtask before asserting, so it does not catch this. A consumer who reports validity in the same turn still sees the previous state.

- Status: open

### Issue 7 -- Severity: bug
- File: src/lib/format.js:68
- Description: `readDate` feeds date-only ISO strings through `new Date(value)`. Per spec those parse as UTC midnight, so `formatDate("2026-01-01", { locale: "en-US", timeZone: "America/Los_Angeles" })` returns `Dec 31, 2025`. The same shift happens with the host timezone when no `timeZone` is passed. The suite only exercises a full ISO datetime with an explicit zone, so calendar dates used for due dates, births, or schedule labels format as the previous day for any zone west of UTC. `rowan-calendar` already round-trips date-only values via `Date.UTC` and would be the right model.
- Suggestion: Detect `YYYY-MM-DD` (and other date-only forms) and format them as UTC calendar dates, or parse them as local calendar dates. Cover `formatDate("2026-01-01", { locale: "en-US", timeZone: "America/Los_Angeles" })` asserting `Jan 1, 2026`.
- Status: open

### Issue 8 -- Severity: bug

### Issue 12 -- Severity: bug
- File: src/popover/popover.js:255
- Description: Popover and dropdown dismiss on a document `pointerdown` whenever `composedPath()` does not include themselves. They are not registered in `overlay-stack`. A popover open inside a `rowan-dialog` therefore closes on backdrop `pointerdown`, and the same gesture’s later `click` hits `event.target === this.#overlay` on the native dialog (`src/dialog/dialog.js:91`) and closes that too. ## Strengths

- FACE on `BaseElement` is the right shape: `form` / `labels` / `validity` / `willValidate` / `setCustomValidity`, `applyValidity` merging consumer custom errors so renders cannot wipe them (F-07), and `#baseDisabledControls` reversing fieldset disablement without re-enabling author-disabled inner controls (F-05).
- Modal family is on native `<dialog>` + `showModal()` / `close()`, with `::backdrop`, `:modal` tests, restore-focus, and reconnect-while-open coverage for dialog and command-palette (F-13/F-14).
- Token architecture now derives component surfaces from the semantic layer; `css:check` exists as a lint (once the Node 20 import is fixed). Forced-colors coverage is present on state-bearing surfaces.
- Table cells, option labels, filter-builder labels, and rich-text runs are created with `textContent` / `createTextNode`. `sanitizeNavigationHref` rejects `javascript:`, `data:`, `file:`, `vbscript:`, and `blob:`. The rich-text document model never accepts HTML as an API value; paste/drop insert plain text.
- `VirtualCollection` is synchronous and deterministic: collision-proof keys, measurements dropped for departed rows, inclusive range edges, scroll anchoring in both `rowan-table` and `rowan-virtual-list` (F-21/F-22).
- Password values are not reflected when `type` is exactly `"password"` (F-08). IME write-back is skipped on `rowan-text-field` (F-09).
- `@rowan-ui/maplibre` has no default style, tile URL, or credential. Attribution hrefs are HTTP(S)-only. Markers/list/table are built with `createElement`/`textContent`; there is no MapLibre `Popup` / `innerHTML`.
- `@rowan-ui/icons` generates Lucide geometry onto a strict SVG allowlist, ships `NOTICE`, and publishes an explicit `files` allowlist that omits tests.
- `useRowanElement` assigns properties only on `Object.is` change and dispatches events through a handler ref (F-03).
- Package `exports` and `sideEffects` match the component folders; `define()` is idempotent; `test:package` actually packs core and maplibre and asserts maplibre-gl does not enter core.

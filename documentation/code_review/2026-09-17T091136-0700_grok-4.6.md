# Rowan React wrapper track — code review

- Date: 2026-09-17
- Model: Grok 4.6
- HEAD: 1594106
- Scope: Whole-tree review of the React wrapper track on `main` (runtime, generator, CEM public-API plugin/check, package exports, peerDependencies, and documentation). Not a branch-vs-main diff.

## Summary

The generated wrapper track is a coherent binding layer: CEM drives checked-in modules, `@rowan-ui/core/react` stays hook-only (no define-all), per-component imports load the matching element module, objects stay property-only, and `onRowan*` maps to `rowan-*`. Runtime tests cover the sprint’s headline contracts (`config` as a property, `onRowanClick`, `disabled={false}`). The remaining defects are real: the documentation site still tells consumers wrappers do not exist, `hidden={false}` takes the React 18 stringify path the track explicitly closed for `disabled`, and wrapper TypeScript props drop function-valued host APIs plus `aria-*`.

### Issue 1 -- Severity: bug
- File: documentation/app.js:1072
- Description: The shipped docs site React page still says the optional React entry “does not provide component wrappers or register custom elements,” then demonstrates hook-only DX (`REACT_TABLE_SNIPPET` at documentation/app.js:105, `NEXT_JS_SNIPPET` at documentation/app.js:155). That is the pre-wrapper contract. Wrappers are now the documented default in README.md, Storybook, CHANGELOG Unreleased, and package exports (`@rowan-ui/core/react/button`, `@rowan-ui/icons/react/icon`, `@rowan-ui/maplibre/react/map`). A consumer who uses the docs site (linked from `npm run documentation`) is told wrappers do not exist and that `@rowan-ui/core/react` is SSR-safe because it never registers elements — true for the hook entry, false for generated wrappers, which import `customElements.define` modules at the top level.
- Suggestion: Rewrite the React page to match README.md / stories/react.mdx: wrappers first (`RowanButton`, `onRowanClick`, `config` as a prop), raw tags + `useRowanElement` as the escape hatch, and “not a Server Component” on wrapper imports. Keep the React 18 raw-tag boolean note only on the tag path.
- Status: open

### Issue 2 -- Severity: bug
- File: src/react/create-wrapper.js:5
- Description: `hidden` is in `ATTRIBUTE_PROPS`, so `hidden={false}` is passed to `createElement` as a host attribute (src/react/create-wrapper.js:48) instead of `element.hidden = false`. React 18 custom-element SSR/attribute updates stringify that as `hidden="false"`. HTML boolean presence treats that as hidden. The track’s explicit contract — and the passing test at src/react/react.test.js:289 — is that `disabled={false}` must not stringify; `disabled` avoids the bug only because it is not in this set and is assigned as a property. `wrapper-props.d.ts:21` types `hidden?: boolean`, so TypeScript will happily accept the broken call.
- Suggestion: Keep `hidden` off the attribute path (assign `element.hidden = value` like `disabled`), or omit the attribute when the value is false and only stamp it when true. Add the same SSR + upgraded-host assertions already used for `disabled`.
- Status: open

### Issue 3 -- Severity: bug
- File: src/react/wrapper-props.d.ts:8
- Description: `HostPropertyKeys` drops every function-typed host field (`NonNullable<Element[Key]> extends (...args: never[]) => unknown ? never : Key`). The hook types in src/react/index.d.ts:12–17 keep `render*` callbacks on purpose. Wrapper runtime would assign them (src/react/create-wrapper.js:53), but TypeScript rejects `<RowanVirtualList renderItem={...} />`, `<RowanSlider formatValue={...} />`, and `<RowanTrendChart valueFormatter={...} />`. Those are the documented property-only APIs for those elements (src/virtual-list/virtual-list.js:25, src/slider/slider.js:302, src/trend-chart/trend-chart.js:75). Unions such as `itemKey: string | function` still survive; pure function props do not.
- Suggestion: Reuse the hook’s `RowanPropertyKeys` rule (allow `render*` and other documented function properties; still exclude methods). Type-test `renderItem` / `formatValue` / `valueFormatter` on the generated wrappers.
- Status: open

### Issue 4 -- Severity: bug
- File: src/react/wrapper-props.d.ts:13
- Description: Generated wrappers are `ForwardRefExoticComponent<RowanWrapperProps<...> & RefAttributes<...>>`, so extra props are type errors. Runtime forwards `aria-*`, `data-*`, `lang`, `dir`, and (as a property) `tabIndex` (src/react/create-wrapper.js:48 and :53). The typed surface only lists `children`, `className`, `id`, `slot`, `style`, `title`, `role`, and `hidden`. `<RowanButton aria-label="Save" />` and `data-testid` therefore fail typecheck while working at runtime. The tag JSX path in src/react/index.d.ts:47 gets these through `React.HTMLAttributes`.
- Suggestion: Intersect with `React.AriaAttributes`, a `data-*` index, and the global host fields the runtime already special-cases (`lang`, `dir`, `tabIndex`). Avoid dumping all of `HTMLAttributes` if that would type `onClick` / `onChange` as if they were `onRowan*` mappings.
- Status: open

### Issue 5 -- Severity: bug
- File: src/react/create-wrapper.js:53
- Description: Association attributes are not in `ATTRIBUTE_PROPS`. `<RowanContextMenu for="project-target">` and `<RowanFormField for="workspace">` assign `element.for = "..."`, which does not run `forTarget` / `htmlFor` (src/context-menu/context-menu.js:119, src/form-field/form-field.js:156) and does not set the `for` attribute. The tag JSX types special-case this (`RowanAssociationAttributeProperties` in src/react/index.d.ts:44). Wrapper types expose `forTarget` / `htmlFor` instead, so TypeScript users can bind correctly; JavaScript users copying the HTML `for` examples get a silent no-op.
- Suggestion: Treat `for` like the tag path: if the host has `htmlFor` or `forTarget`, stamp the `for` attribute (or assign those setters). Accept `for` on `RowanWrapperProps` for those elements.
- Status: open

### Issue 6 -- Severity: bug

### Issue 8 -- Severity: suggestion
- File: src/react/use-rowan-element.js:34
- Description: Host discovery runs in `useLayoutEffect` (src/react/use-rowan-element.js:29), but property writes — including `disabled={true}` and table `config` — run in `useEffect` (line 34), after paint. Wrappers put every non-allowlisted field on that path (src/react/create-wrapper.js:53), so they also never appear in `renderToStaticMarkup`. `disabled={false}` is correctly absent; `disabled={true}` is also absent until after first paint, so a client-rendered “disabled” button can receive a click for a frame. README documents property assignment as the boolean strategy, so this is an accepted SSR tradeoff, but the after-paint gap is still user-visible.
- Suggestion: Assign properties in `useLayoutEffect` (same turn as host attach) so `disabled` / `open` apply before paint. Optionally reflect true booleans and scalar strings as attributes for SSR while keeping false booleans off the attribute path.
- Status: open

### Issue 9 -- Severity: suggestion
- File: src/react/use-rowan-element.js:44
- Description: The applied-property map only writes keys present in this render’s `properties` object. `create-wrapper.js:35` skips `undefined`, so `<RowanButton disabled={true} />` followed by `<RowanButton />` leaves `element.disabled === true`. Controlled `disabled={flag}` is fine; omitting a previously set prop does not restore the element default.
- Suggestion: When the host is unchanged, assign `undefined` (or a documented default) for keys that dropped out of `properties`, or document that wrappers are last-write-wins and omitted props stick.
- Status: open

## What looks correct

- Generator (`scripts/generate-react-wrappers.mjs`) maps `rowan-click` → `onRowanClick`, `rowan-location-activate` → `onRowanLocationActivate`, pins button/table/icon/map imports, and is wired into `npm run analyze`. CI `Verify generated artifacts` includes `src/react/generated` and both package trees.
- CEM plugin + `check-cem-public-api.mjs` strip private/lifecycle members and pin `config`/`selected` as non-attributes, `rowan-click`, icon `name`, and map `locations` / `rowan-location-activate`.
- `@rowan-ui/core/react` does not import element modules. `@rowan-ui/core/react/button` imports `../../button/button.js`. `@rowan-ui/core/react/components` is a re-export barrel. `sideEffects` lists registration modules only.
- `disabled={false}` is a property write, omitted from SSR markup, and covered by tests (src/react/react.test.js:289–308). Table `config` is not reflected as an attribute (src/react/react.test.js:270).
- Icons HTML/SVG remain core-free: `packages/icons/src/element.js` extends `HTMLElement` and does not import `@rowan-ui/core`. Only `packages/icons/src/react/generated/icon.js` imports core, and that is documented. `@rowan-ui/core` is an optional peer on icons.
- MapLibre wrapper imports `../../map/map.js`, which `define`s `rowan-maplibre-map`.
- peerDependencies: `react` is optional on all three packages so HTML/SVG consumers are not forced to install it.
